# promptxray — пошаговая инструкция

Этот файл нужен только тебе. Перед публикацией на GitHub его можно удалить или
оставить — он никому не мешает.

---

## 0. Что вообще делает эта программа

У человека есть промпт-классификатор: текст промпта, который просит модель
вернуть одну метку («spam», «urgent», «normal»). И есть размеченный CSV: текст +
правильный ответ. Обычные инструменты скажут «точность 83%». Твой инструмент
говорит другое: **вот эта строка промпта даёт +0.125 к метрике, а вот эта —
отнимает 0.096, а остальные четыре не делают вообще ничего.**

Как он это узнаёт: убирает по одному блоку промпта, прогоняет датасет заново и
смотрит, насколько просела метрика. Это метод occlusion из объяснимого ML — тот
самый, про который у тебя бакалаврская работа, только «признаки» здесь не пиксели,
а куски промпта.

## 1. Что нужно установить (один раз)

1. **Python 3.10 или новее.** Проверь: открой PowerShell и набери `python
   --version`. Если пусто или ошибка — ставь с python.org, **обязательно
   поставив галочку «Add Python to PATH»** на первом экране установщика.
2. **Git.** `git --version`. Если нет — git-scm.com, все настройки по умолчанию.
3. **VS Code** — у тебя уже есть.
4. **Расширение Python для VS Code.** В VS Code слева иконка кубиков
   (Extensions), в поиске «Python», издатель Microsoft, кнопка Install.

---

## 2. Куда положить проект

Распакуй архив в `D:\Git\github\promptxray` (у тебя там уже лежит schemalink,
пусть всё будет в одном месте).

Открой папку в VS Code: `File → Open Folder…` → выбираешь `promptxray`.

Дальше вся работа идёт в **терминале внутри VS Code**: меню `Terminal → New
Terminal`, снизу откроется PowerShell, и он уже будет находиться в папке проекта.
Все команды ниже набираются именно там.

## 3. Виртуальное окружение

Это отдельная «песочница» для библиотек проекта, чтобы они не смешивались с
системным Python. Делается один раз.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Если вторая команда ругается на политику выполнения скриптов, выполни один раз:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

и повтори активацию. Признак успеха: в начале строки терминала появилось
`(.venv)`.

## 4. Установка и первый запуск

```powershell
pip install -e ".[dev]"
```

`-e` значит «editable»: пакет ставится ссылкой на папку, поэтому любое твоё
изменение в коде действует сразу, без переустановки.

Проверь, что всё живо:

```powershell
pytest -q
```

Должно быть `13 passed`. Тесты работают на встроенной фейковой модели, поэтому
не требуют ни интернета, ни ключей, ни денег.

Теперь главная команда:

```powershell
promptxray ablate --prompt examples/prompt.txt --data examples/data.csv --provider mock --report report.html
```

В терминале появится таблица блоков, а рядом с проектом — файл `report.html`.
Открой его двойным кликом в браузере. Внутри — твой промпт, раскрашенный по
блокам: синий значит «без этого блока метрика падает», янтарный — «без него
метрика растёт», пунктир — «блок ни на что не влияет». Наведи курсор на любой
блок: всплывёт объяснение, почему он получил такой цвет, какие конкретные
примеры сломались или починились, и что с этим делать. Это и есть тот самый
скриншот, ради которого проект существует.

## 5. Что лежит в каждом файле

| Файл | Зачем он |
| --- | --- |
| `src/promptxray/blocks.py` | Режет промпт на блоки по пустым строкам. Помечает блоки, которые нельзя удалять (`{input}` и `[[keep]]`). |
| `src/promptxray/dataset.py` | Читает CSV/JSONL. Здесь же логика выбора подвыборки для абляции. |
| `src/promptxray/providers.py` | Общение с моделью. Три бэкенда: `mock` (фейковый, для демо и тестов), OpenAI-совместимый (в том числе Ollama), Anthropic. Написано на голой стандартной библиотеке — у пакета ноль зависимостей. |
| `src/promptxray/cache.py` | SQLite-кэш ответов. Ключ — хеш точного текста промпта + модель. Благодаря ему повторный запуск бесплатный. |
| `src/promptxray/metrics.py` | Матрица ошибок, precision/recall/F1. Чистый Python, без numpy. |
| `src/promptxray/ablation.py` | Сердце проекта: убирает блоки по одному и считает дельты. |
| `src/promptxray/report.py` | Генерирует HTML-отчёт одним файлом, без внешних CSS и JS. |
| `src/promptxray/cli.py` | Разбор аргументов командной строки: `run`, `ablate`, `diff`. |
| `examples/` | Демо-промпт и демо-датасет, специально составленные так, чтобы был виден и полезный блок, и вредный, и четыре бесполезных. |
| `tests/` | 13 тестов. |
| `.github/workflows/ci.yml` | GitHub сам будет прогонять тесты при каждом пуше. |

## 6. Как запустить на настоящей модели

**Бесплатно, локально, через Ollama** (скачай с ollama.com, потом
`ollama pull llama3.2`):

```powershell
promptxray ablate --prompt examples/prompt.txt --data examples/data.csv --provider ollama --model llama3.2 --report report.html
```

**Через OpenAI** (нужен ключ и немного денег на балансе):

```powershell
$env:OPENAI_API_KEY = "sk-..."
promptxray ablate --prompt examples/prompt.txt --data examples/data.csv --provider openai --model gpt-4o-mini --subset-size 40 --report report.html
```

Ключ пишется в переменную окружения, а не в код. Никогда не коммить ключ в
репозиторий: если он попадёт в git, его придётся отзывать.

## 7. Публикация на GitHub

Создай пустой репозиторий на github.com (кнопка New, имя `promptxray`, **без**
галочек «Add README» и «Add .gitignore» — они у тебя уже есть). Затем в
терминале VS Code:

```powershell
git init
git add .
git commit -m "promptxray: prompt-level ablation for LLM classifiers"
git branch -M main
git remote add origin https://github.com/godwire/promptxray.git
git push -u origin main
```

После пуша зайди в настройки репозитория и заполни **About** справа вверху:
описание `Find out which line of your prompt is causing your classifier's
errors` и темы (topics): `llm`, `evaluation`, `prompt-engineering`,
`explainability`, `python`. Темы — это то, по чему проект находят.

## 8. Публикация в PyPI (чтобы работал `pip install promptxray`)

Имя `promptxray` на PyPI свободно — я проверил. Не тяни, займи его.

1. Зарегистрируйся на pypi.org, включи 2FA (у тебя уже был такой опыт с npm).
2. Создай API-токен: Account settings → API tokens → Add API token.
3. В терминале:

```powershell
pip install build twine
python -m build
twine upload dist/*
```

Логин: `__token__`, пароль: сам токен целиком, вместе с префиксом `pypi-`.

## 9. Что делать дальше, чтобы проект заметили

Репозиторий сам по себе звёзд не набирает. Работает связка «статья с цифрами →
ссылка на репозиторий».

**Шаг 1. Реальный кейс.** Возьми публичный датасет с классификацией (подойдёт
любой набор для детекции токсичности — заодно сошьётся с твоим дипломом),
напиши для него промпт как обычный человек, прогони `ablate` на дешёвой модели.
Ты почти наверняка обнаружишь, что половина инструкций ничего не делает.
Сохрани отчёт.

**Шаг 2. Статья.** На Medium, с заголовком в духе «Я измерил каждую строку
своего промпта, и половина оказалась бесполезной». Структура: проблема (метрика
есть, причины нет) → что такое occlusion и почему это старая идея из XAI →
конкретные цифры на реальном датасете → скриншот отчёта → ссылка на репозиторий.
Цифры и скриншот важнее кода.

**Шаг 3. Куда нести.** r/LocalLLaMA, r/MachineLearning (там нужен тег [P] —
project), Hacker News (Show HN), LinkedIn. Не постить везде в один день —
разнеси на неделю, чтобы успевать отвечать в комментариях. Ответы на комментарии
дают больше, чем сам пост.

**Шаг 4. Дорожная карта v0.2**, если пойдёт отклик:
- поддержка few-shot примеров как отдельного типа блока;
- групповая абляция (убирать пары блоков — так видно взаимодействия);
- команда `suggest`: автоматически предложить укороченный промпт из блоков,
  которые реально работают;
- pytest-плагин, чтобы `--fail-under` встраивался в чужие тесты.

Не делай всё сразу. Опубликуй v0.1, дождись реакции, дальше двигайся по тому,
что попросят люди.

## 10. Что сказать на собеседовании

Не «я сделал пет-проект». А так: «Есть известная проблема — промпты пишут на
глаз и не умеют измерять вклад отдельных инструкций. Я взял occlusion-атрибуцию
из объяснимого ML, применил её к блокам промпта и упаковал в инструмент. Главная
инженерная задача была в стоимости: наивно это N×M вызовов API, я снизил их
кэшированием по хешу промпта и подвыборкой, обогащённой ошибками». Дальше
показываешь отчёт. Это разговор на уровень выше, чем «я написал CRUD».
